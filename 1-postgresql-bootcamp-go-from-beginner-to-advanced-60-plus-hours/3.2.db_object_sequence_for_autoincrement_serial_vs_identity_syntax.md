In PostgreSQL, a **sequence** is a special database object used to **generate a series of numbers automatically**, usually for **auto-incrementing IDs**.

You normally see sequences when using **`SERIAL`**, **`BIGSERIAL`**, or **identity columns**. sequences generate values for **primary keys**.

---

# 1️⃣ What a Sequence Is

A **sequence** is basically a **number generator stored in the database**.

It produces numbers like:

```
1
2
3
4
5
...
```

Every time you ask the sequence for a value → it returns the **next number**.

---

# 2️⃣ Example: How Sequences Are Created

When you create a table like this:

```sql
CREATE TABLE actors (
    actor_id SERIAL PRIMARY KEY,
    name TEXT
);
```

PostgreSQL automatically creates:

```
actors_actor_id_seq
```

So internally PostgreSQL does something like:

```sql
CREATE SEQUENCE actors_actor_id_seq;
```

and sets the default value of the column:

```sql
actor_id DEFAULT nextval('actors_actor_id_seq')
```

---

# 3️⃣ How It Works During INSERT

Example table:

```
actors
---------
actor_id | name
```

Insert:

```sql
INSERT INTO actors(name)
VALUES ('Tom Hanks');
```

PostgreSQL automatically calls:

```sql
nextval('actors_actor_id_seq')
```

Sequence returns:

```
1
```

Row inserted:

```
1 | Tom Hanks
```

Next insert:

```sql
INSERT INTO actors(name)
VALUES ('Brad Pitt');
```

Sequence returns:

```
2
```

Result:

```
1 | Tom Hanks
2 | Brad Pitt
```

---

# 4️⃣ Important Sequence Functions

### Get next value

```sql
SELECT nextval('actors_actor_id_seq');
```

Example output:

```
3
```

---

### Get current value

```sql
SELECT currval('actors_actor_id_seq');
```

⚠️ Only works **after nextval() in that session**.

---

### Reset sequence

```sql
SELECT setval('actors_actor_id_seq', 100);
```

Next value will be:

```
101
```

---

# 5️⃣ Inspecting a Sequence

You can check a sequence definition:

```sql
\d actors_actor_id_seq
```

Example output might show:

```
Start: 1
Increment: 1
Min value: 1
Max value: 9223372036854775807
```

---

# 6️⃣ Why PostgreSQL Uses Sequences

Sequences solve **concurrency problems**.

Imagine:

```
10 users inserting rows at the same time
```

Without sequences:

```
SELECT MAX(id) + 1
```

would cause **duplicate IDs**.

Sequences are:

* **atomic**
* **thread-safe**
* **very fast**

So PostgreSQL guarantees:

```
each call → unique number
```

---

# 7️⃣ Why You See Sequences in Your Database

Your tables probably have something like:

```sql
actor_id SERIAL
movie_id SERIAL
customer_id SERIAL
```

That automatically created sequences like:

```
actors_actor_id_seq
movies_movie_id_seq
customers_customer_id_seq
```

---

# 8️⃣ Modern PostgreSQL Alternative (Better)

Instead of `SERIAL`, modern PostgreSQL uses **IDENTITY columns**.

Example:

```sql
CREATE TABLE actors (
    actor_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
);
```

This still uses sequences internally but is **SQL standard compliant**.

# 🔑 Simple Mental Model

Think of a **sequence** like a **ticket machine**:

```
Take ticket → 1
Next ticket → 2
Next ticket → 3
```

Each insert **takes the next ticket**.
