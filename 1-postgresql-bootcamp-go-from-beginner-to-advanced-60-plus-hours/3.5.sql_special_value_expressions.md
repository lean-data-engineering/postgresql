Excellent question — this touches a subtle SQL concept.

The short answer:

> **`CURRENT_DATE` is not a normal function in PostgreSQL. It is a SQL standard special keyword (or special value expression), which is why it does not use parentheses.**

So it behaves like a scalar function but **syntactically it is not written like one**.

---

# 1️⃣ `CURRENT_DATE` Is a SQL Special Value Expression

In the SQL standard, things like:

```
CURRENT_DATE
CURRENT_TIME
CURRENT_TIMESTAMP
LOCALTIME
LOCALTIMESTAMP
```

are defined as **special value expressions**, not regular functions.

So the correct syntax is:

```sql
SELECT CURRENT_DATE;
```

not

```sql
SELECT CURRENT_DATE();
```

---

# 2️⃣ Why SQL Designed It This Way

Historically, SQL treats these values like **keywords that represent system values**.

Similar to:

```
TRUE
FALSE
NULL
```

They behave more like **constants provided by the system** rather than functions.

Example:

```sql
SELECT CURRENT_DATE;
```

Output:

```
2026-03-11
```

---

# 3️⃣ Comparison With Real Functions

### Real scalar function

```sql
SELECT NOW();
```

Parentheses required.

---

### Special SQL expression

```sql
SELECT CURRENT_DATE;
```

No parentheses.

---

# 4️⃣ PostgreSQL Equivalent Function

Even though `CURRENT_DATE` is not a function, PostgreSQL can produce the same value using a function.

Example:

```sql
SELECT NOW()::date;
```

or

```sql
SELECT CURRENT_TIMESTAMP::date;
```

---

# 5️⃣ Another Example of SQL Special Expressions

These also **don't use parentheses**.

```sql
SELECT CURRENT_TIME;
SELECT CURRENT_TIMESTAMP;
SELECT LOCALTIME;
SELECT LOCALTIMESTAMP;
```

But this **is a function**:

```sql
SELECT clock_timestamp();
```

---

# 6️⃣ Important Behavior Difference

`CURRENT_DATE` is **transaction stable**.

Example:

```sql
BEGIN;

SELECT CURRENT_TIMESTAMP;
SELECT CURRENT_TIMESTAMP;
```

Both return **same value** within the transaction.

But:

```sql
SELECT clock_timestamp();
```

Returns **different values every call**.

---

# 7️⃣ Simple Mental Model

| Type              | Example        | Parentheses |
| ----------------- | -------------- | ----------- |
| Scalar function   | `NOW()`        | ✅           |
| SQL special value | `CURRENT_DATE` | ❌           |
| Constant          | `NULL`         | ❌           |

So `CURRENT_DATE` behaves like a **system constant evaluated at runtime**.

---

# ✅ Final Takeaway

Your assumption:

> if CURRENT_DATE is a scalar/row function why no parens?

Correction:

* It **acts like a scalar value per row**
* But it is **not technically a function**
* It is a **SQL standard special value expression**
