**Reason**

The error is coming from **pgAdmin's UI**, not the container filesystem. The `/sql` path exists in the container, but pgAdmin's file browser is sandboxed and doesn't browse the container filesystem directly.

**Fix: Use pgAdmin's storage path instead**

pgAdmin stores files under `/var/lib/pgadmin/storage/`. You need to copy your SQL files there:

**do it via docker-compose** by mounting directly into pgAdmin's storage path:

```yaml
pgadmin:
  volumes:
    - type: volume
      source: pgadmin-data
      target: /var/lib/pgadmin
    - type: bind
      source: /Users/apatel/Documents/.../sample_data
      target: /var/lib/pgadmin/storage/admin_example.com/sql  # ← change this
```

pgAdmin replaces **only the `@` symbol** with an underscore `_` when creating the storage folder.

```
admin@example.com
     ^
     @ → _

becomes: admin_example.com
```

The `.` in `example.com` stays as-is because dots are perfectly valid in Linux directory names.

So the rule is simply:
> **`@` is not allowed in directory names on most filesystems, so pgAdmin swaps it for `_`.**

You can verify this yourself — if your email were `john.doe@my-company.org`, the folder would be:

```
/var/lib/pgadmin/storage/john.doe_my-company.org/
```

# The Two Mounts in Your docker-compose**

## The Two Mounts in Your docker-compose

### Mount 1 — Named Volume

```yaml
- type: volume
  source: pgadmin-data
  target: /var/lib/pgadmin
```

This is a **Docker-managed named volume**. Docker creates and owns this storage on your host machine. It persists pgAdmin's internal data — your server connections, user settings, query history, etc. — across container restarts. You don't control where it lives on your Mac; Docker manages it under `/var/lib/docker/volumes/`.

---

### Mount 2 — Bind Mount

```yaml
- type: bind
  source: /Users/apatel/.../sample_data
  target: /sql
```

This is a **bind mount** — it maps a specific folder on your Mac directly into the container. Whatever files exist in `sample_data` on your Mac appear live at `/sql` inside the container. Changes on either side are reflected immediately.

The problem is `/sql` is just a raw filesystem path. **pgAdmin's file browser doesn't browse the container filesystem freely** — it's sandboxed to `/var/lib/pgadmin/storage/` for security reasons. So even though `/sql` exists in the container, pgAdmin's UI can't see it.

---

### Why `admin@example.com` becomes `admin_example.com`

pgAdmin uses your login email to create a personal storage folder for each user, but `@` and `.` are **not valid characters in Linux directory names** (well, `.` is valid but avoided for safety). So pgAdmin sanitizes the email:

```
admin@example.com  →  admin_example.com
    ^       ^
    @  →  _     (@ replaced with underscore)
```

So the folder `/var/lib/pgadmin/storage/admin_example.com/` is simply pgAdmin saying *"this storage belongs to the user <admin@example.com>"*.

# i am moving from mac laoptop to linux laptop. can i have back up of networks , volumes . and migrate them from mac to linux

Yes, you can migrate everything. Here's how:

---

## 1. Backup Volumes (on your Mac)

```bash
# Backup pgdata (postgres data)
docker run --rm \
  -v pgdata:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/pgdata_backup.tar.gz -C /data .

# Backup pgadmin-data
docker run --rm \
  -v pgadmin-data:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/pgadmin_backup.tar.gz -C /data .
```

This spins up a temporary Alpine container, mounts your volume, and tarballs it into your current directory on the Mac.

---

## 2. Networks

**You don't need to back up networks.** Docker networks are just configuration — your `docker-compose.yml` already defines the `backend` network. When you run `docker compose up` on Linux, Docker recreates it automatically.

---

## 3. Transfer to Linux

Copy your backup files and docker-compose.yml to your Linux machine:

```bash
scp pgdata_backup.tar.gz pgadmin_backup.tar.gz docker-compose.yml user@linux-machine:~/postgres-migration/
```

---

## 4. Restore Volumes (on your Linux machine)

```bash
# Create the volumes first
docker volume create pgdata
docker volume create pgadmin-data

# Restore pgdata
docker run --rm \
  -v pgdata:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/pgdata_backup.tar.gz -C /data

# Restore pgadmin-data
docker run --rm \
  -v pgadmin-data:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/pgadmin_backup.tar.gz -C /data
```

---

## 5. Update the Bind Mount Path

Your docker-compose has a Mac-specific path — update it for Linux:

```yaml
# Mac (old)
source: /Users/apatel/Documents/.../sample_data

# Linux (new)
source: /home/apatel/Documents/.../sample_data
```

Then just run:

```bash
docker compose up -d
```

Everything — your postgres data, pgAdmin saved servers, and settings — will be exactly as you left them on your Mac.
