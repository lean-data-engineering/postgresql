Yes — **`SERIAL` is *not* part of the SQL standard.**
It is a **PostgreSQL-specific convenience feature**.

Modern SQL standard uses **IDENTITY columns** instead.

---

# 1️⃣ What `SERIAL` Really Is in PostgreSQL

When you write:

```sql
CREATE TABLE actors (
    actor_id SERIAL PRIMARY KEY
);
```

PostgreSQL silently expands it into **three things**.

### 1️⃣ Create a sequence

```sql
CREATE SEQUENCE actors_actor_id_seq;
```

### 2️⃣ Create column

```sql
actor_id INTEGER NOT NULL
```

### 3️⃣ Set default value

```sql
DEFAULT nextval('actors_actor_id_seq')
```

So internally it becomes something like:

```sql
CREATE TABLE actors (
    actor_id INTEGER NOT NULL DEFAULT nextval('actors_actor_id_seq'),
    PRIMARY KEY (actor_id)
);
```

---

# 2️⃣ Why `SERIAL` Is Not Standard

`SERIAL` is:

* ❌ not part of SQL standard
* ❌ not supported in many databases
* ✅ specific to PostgreSQL

Other databases implemented **auto-increment differently**.

Examples:

| Database   | Syntax               |
| ---------- | -------------------- |
| PostgreSQL | `SERIAL`             |
| MySQL      | `AUTO_INCREMENT`     |
| SQL Server | `IDENTITY`           |
| Oracle     | sequences + triggers |

Because of this inconsistency, the SQL standard introduced **IDENTITY columns**.

---

# 3️⃣ SQL Standard Solution: `IDENTITY`

Modern PostgreSQL supports the standard syntax:

```sql
CREATE TABLE actors (
    actor_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
);
```

Two variants exist.

---

### ALWAYS

Database **always generates value**.

```sql
GENERATED ALWAYS AS IDENTITY
```

Insert:

```sql
INSERT INTO actors VALUES (10);
```

❌ error

Because database controls the value.

---

### BY DEFAULT

User **can override**.

```sql
GENERATED BY DEFAULT AS IDENTITY
```

Example:

```sql
INSERT INTO actors(actor_id) VALUES (100);
```

Allowed.

---

# 4️⃣ Why PostgreSQL Still Supports SERIAL

Backwards compatibility.

Millions of old schemas use:

```sql
SERIAL
BIGSERIAL
SMALLSERIAL
```

So PostgreSQL keeps supporting it.

But **new projects should prefer IDENTITY**.

---

# 5️⃣ SERIAL Variants

| Type          | Column Type |
| ------------- | ----------- |
| `SMALLSERIAL` | smallint    |
| `SERIAL`      | integer     |
| `BIGSERIAL`   | bigint      |

Example:

```sql
CREATE TABLE movies (
    movie_id BIGSERIAL PRIMARY KEY
);
```

---

# 6️⃣ Practical Recommendation

Modern PostgreSQL (recommended):

```sql
CREATE TABLE users (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
);
```

Old PostgreSQL style:

```sql
id SERIAL PRIMARY KEY
```

Both still work.

---

# 🧠 Key Takeaway

| Feature  | Standard SQL | PostgreSQL |
| -------- | ------------ | ---------- |
| SERIAL   | ❌            | ✅          |
| IDENTITY | ✅            | ✅          |

So:

> **SERIAL is PostgreSQL shorthand for sequence + default nextval()**
